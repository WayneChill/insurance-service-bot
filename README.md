# 保險業務發展小幫手 LINE Bot

> 合併產險助手 + 保服助手，整合業務開發、保服追蹤、新件追蹤、扣款失敗追蹤、行程管理於一體。

## 快速設定流程

### 1. LINE Developers 申請
1. 前往 https://developers.line.biz/
2. 建立 Provider → 建立 Messaging API Channel
3. 取得 `Channel Secret` 和 `Channel Access Token`
4. 在 Messaging API 設定頁關閉「自動回應訊息」

### 2. Google Sheets 設定
1. 前往 https://console.cloud.google.com/
2. 建立新專案 → 啟用 Google Sheets API 和 Google Drive API
3. 建立服務帳號（Service Account）→ 下載 JSON 金鑰，重新命名為 `credentials.json`
4. 在 Google Sheets 建立一個空白試算表，分享給服務帳號 email（編輯者權限）
5. 從試算表網址取得 Sheet ID：
   `https://docs.google.com/spreadsheets/d/【這段就是ID】/edit`

### 3. 本地測試
```bash
pip install -r requirements.txt
# 填寫 config.txt 各項設定值
python app.py

# 另開終端，使用 ngrok 建立公開網址
ngrok http 5000
# 將 https://xxxx.ngrok.io/callback 貼到 LINE Bot Webhook URL
```

### 4. 部署到 Railway
1. 上傳程式碼到 GitHub（Private repo）
2. Railway → New Project → Deploy from GitHub repo
3. 在 Variables 頁面設定所有環境變數
4. `credentials.json` 轉成 base64 放入 `GOOGLE_CREDENTIALS_B64` 環境變數
5. 取得部署網址，設定到 LINE Bot Webhook URL：`https://你的網址/callback`

## 環境變數

| 變數名稱 | 說明 |
|---------|------|
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Bot Channel Access Token |
| `LINE_CHANNEL_SECRET` | LINE Bot Channel Secret |
| `LINE_USER_ID` | 接收推播的 LINE User ID |
| `GOOGLE_SHEET_ID` | Google 試算表 ID |
| `DRIVE_FOLDER_ID` | Google Drive 資料夾 ID（存放 Excel 保單檔） |
| `GOOGLE_CREDENTIALS_B64` | credentials.json 的 base64 編碼（Railway 用）|
| `GOOGLE_CREDENTIALS_FILE` | credentials.json 路徑（本地測試用，預設 credentials.json）|

## 指令一覽

### 查詢與保服

| 指令 | 說明 |
|------|------|
| `查詢` | 輸入客戶姓名，顯示保單資料卡片（含信用卡） |
| `新增保服` | 新增保服案件（對話框引導） |
| `保服` | 查看所有待處理保服案件列表 |
| `記錄 C001 備註` | 更新保服案件備註 |

### 新件追蹤

| 指令 | 說明 |
|------|------|
| `新增新件` | 新增新件追蹤（對話框引導，輸入姓名＋保險公司） |
| `新件` | 查看新契約追蹤列表（核保中／照會中／發單中） |
| `更新新件 N001 階段` | 更新新件進度，例：`更新新件 N001 發單中` |
| `記錄 N001 備註` | 更新新件備註 |

### 業務與增員

| 指令 | 說明 |
|------|------|
| `新增銷售` | 新增銷售追蹤（對話框引導） |
| `銷售` | 查看銷售追蹤列表 |
| `更新銷售 B001 階段` | 更新銷售進度，例：`更新銷售 B001 建議書` |
| `新增增員` | 新增增員追蹤（對話框引導） |
| `增員` | 查看增員追蹤列表 |
| `更新準增 R001 階段` | 更新增員進度，例：`更新準增 R001 約聊聊` |
| `記錄 B001 備註` | 更新銷售／增員備註（R 開頭為增員） |

### 扣款失敗

| 指令 | 說明 |
|------|------|
| `扣款失敗` | 查看轉帳未成功／信用卡請款失敗列表（狀態非已完成） |
| `記錄 P001 備註` | 更新扣款失敗備註 |

卡片底部按鈕可直接更新狀態：待處理 → 已聯絡 → 已送出 → 已完成

### 產險與壽險

| 指令 | 說明 |
|------|------|
| `產險` | 查看 60 天內到期產險，可直接更新聯絡狀態 |
| `壽險` | 查看當日壽星＋保單周年名單 |

### 行程

| 指令 | 說明 |
|------|------|
| `行程` | 今日行程 |
| `本周行程` | 本週行程列表 |
| `本月行程` | 本月行程列表 |
| `新增行程` | 新增行程（日期用民國7碼如 `1150331`，時間4碼如 `1400`） |

### 其他

| 指令 | 說明 |
|------|------|
| `待辦` | 顯示今日待辦彙整（產險急件、新件、保服、扣款失敗、銷售、增員） |
| `早報` | 手動觸發今日早報 |
| `新增卡片` | 新增客戶信用卡資料 |

## 排程

| 時間 | 功能 |
|------|------|
| 每日 08:00（台灣時間） | **每日早報**：行程區、壽險區、產險區、新件區、保服區、💳 保費區（扣款失敗各狀態件數）、銷售區、增員區 |
| 每日 20:00（台灣時間） | **晚間待辦提醒**：產險急件、新件追蹤、保服未完成、扣款失敗、銷售待跟進、增員待跟進 |

早報也可以隨時發送「早報」手動觸發。若建立早報失敗，會自動重試最多 3 次（間隔 30 秒）。

## Google Sheets 工作表結構

系統啟動時若工作表不存在，會自動建立：

| 工作表名稱 | 欄位 | 說明 |
|-----------|------|------|
| 保服案件 | ID, 客戶姓名, 服務項目, 保單號碼, 狀態, 備註, 建立時間, 更新時間 | 保服案件追蹤 |
| 業務追蹤 | ID, 姓名, 電話, 階段, 備註, 建立時間, 更新時間 | 銷售開發追蹤 |
| 增員追蹤 | ID, 姓名, 電話, 階段, 備註, 建立時間, 更新時間 | 增員追蹤 |
| 新契約追蹤 | ID, 姓名, 保險公司, 階段, 備註, 建立時間, 更新時間 | 新件核保中／照會中／發單中 |
| 扣款失敗 | ID, 公司, 要保人, 保單號碼, 類別, 轉帳日, 保費, 狀態, 備註, 更新時間 | 轉帳未成功／信用卡請款失敗追蹤 |
| 信用卡 | 姓名, 銀行名, 卡號前4碼, 效期, 備註保單 | 客戶信用卡資料 |
| 行程 | ID, 日期, 時間, 類型, 標題, 備註, 建立時間 | 行程管理 |
| 待確認狀態 | user_id, action, timestamp | 對話暫存（10分鐘自動過期） |
